# AI Scan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On every rental listing, the extension shows an AI text check (our rules applied by Azure OpenAI) plus a Timișoara price check: warnings in the panel, a summary line on the collapsed badge, and red underlines on the page. It never shows anything that reads as "safe".

**Architecture:**
- `packages/shared` holds the rule ids, labels, severities and the `/api/scan` contract.
- `apps/web` adds `POST /api/scan`. It redacts phones and emails, calls a switchable provider (`SCAN_PROVIDER=azure-openai|mock`, unset = off), keeps only exact quotes, adds the price check, and falls back to recorded answers for the demo listings.
- `apps/extension` reads title, price and description, asks the background worker (which keeps a session cache), renders the result in the badge, and underlines the quotes on the page.

**Tech stack:** TypeScript, Next.js 16.4 route handlers, `openai` npm package (Azure client), WXT MV3 extension, Vitest + jsdom, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-14-ai-scan-design.md` (approved). Read it with this plan.

## Context

- Most real listings never carry a `VC-` code, so today the extension says only "⚪ Not verified" on them.
- The team wants a wow moment and something useful on listings without a code.
- The user chose: AI applies **our written rules** (approach A), **Azure OpenAI** as the provider, a price check against published Timișoara averages, and an AI summary line on the collapsed badge.
- A teammate provides the Azure deployment by **Sun 15 Nov 09:00**. Tasks 1–8 build and test entirely on the mock. Task 9 needs the live model.

## Review Focus

1. **Cedilla vs comma diacritics.** Romanian text often uses ş/ţ (cedilla) where the model writes ș/ț (comma). Expected: the quote still matches and gets underlined. Pinned by `normalizeForMatch` tests (Task 1) and highlight tests (Task 8).
2. **Non-breaking spaces and line breaks.** OLX descriptions use `&nbsp;` and `<br>`. Expected: a quote written with plain spaces still matches. Pinned in Tasks 1 and 8.
3. **Moving to another listing in the same tab.** Expected: a slow scan for the previous listing never paints on the new one. Pinned in the Task 6 watcher test.
4. **Content-filter or prompt-injection text.** Expected: Azure's filter error comes back as "unavailable" (or the saved result on demo pages), never a crash or a 500. Pinned in the Task 3 Azure provider test and the Task 4 route test.
5. **The page re-renders and drops the underlines.** Expected: they come back from the cached answer without a new AI call. Pinned in the Task 8 highlighter test.

**`runScan` steps:**

**Route behaviour:**

- Every response carries CORS `*`.
- Log only `console.info('scan', { level, warnings, ms, source })`.

**Watcher behaviour:**
- On each run on a listing page, if `readText()` gives text, and the page is a demo listing (`e.listing?.site === 'demo'`) or `isRental(text)` is true, and its `scanCacheKey` changed: start the scan **in parallel** with the check and set `scan: 'loading'`.
- Re-compare the scan key even when the check key is unchanged, since the title can render late.
- The newest scan generation only may paint, the same rule as checks.
- Not a listing → `scan: null`.

**Background:**
- `'scan'` → `browser.storage.session.get(key)`. On a hit, reply from the cache.
- On a miss → `fetchScan`. Store it only when `ok` and `source === 'live'`.
